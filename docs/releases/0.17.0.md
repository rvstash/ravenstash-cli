# Ravenstash CLI 0.17.0

Ravenstash CLI 0.17.0 makes a personal account ready for public packages as soon as you sign in, and keeps one repository or mirror selection per format.

## Update

```bash
rvs update --apply
```

On Debian and Ubuntu installations, `sudo apt update && sudo apt upgrade` installs it as well. For a new installation, see the [quickstart](../quickstart.md).

## Changes

- **Default mirror for personal accounts.** Ravenstash gives every personal account a private mirror of each Ravenstash-provided source. When nothing is selected for pypi, npm, or maven, installs and other reads through `rvs pip`, `rvs uv`, `rvs python -m build`, `rvs npm`, `rvs pnpm`, and `rvs mvn` use the default mirror of that format, so `rvs auth login` followed by `rvs pip install requests` works with no other step. `rvs` names the mirror on standard error and saves nothing. The default never applies to publishing or deletion, organization accounts, commands authenticated with `RVS_TOKEN`, container images and Helm charts, or `rvs art endpoint`, `rvs art native config`, and `rvs art token mint`. A mirror you deleted is not recreated; `rvs art mirror create --format FORMAT --select` adds it again.
- **One selection per format.** `rvs art select TARGET` selects the target for every format it has, and `--format` (repeated or comma-separated) selects only the formats you name. Formats the target lacks keep their selection: selecting `mirror:npmjs` no longer replaces the repository you use for PyPI. `rvs art clear --format FORMAT` clears one format, and `rvs art clear` clears them all.
- **Status per format.** `rvs art status` and `rvs status` show one line per format. Their JSON adds `formats` and `targets.artifacts_by_format`, and keeps the earlier single-target fields, which are filled only when one target is selected for every selected format.
- **Mirror creation reuses an existing mirror.** `rvs art mirror create` reports the account's existing mirror of a source instead of failing.
- **Clearer container messages.** `rvs docker`, `rvs helm`, and `rvs oras` explain how to choose a private repository with the oci format when none is selected. There is no container mirror.

## Configuration upgrade

The first command of this release upgrades `~/.rvs/config.toml` to schema 2 and keeps the original as `config.toml.schema-1.bak`. A selection that named a format keeps that format. A repository selected without a format, which every package tool used before, stays selected for every format until you select the repository again, which then records only the formats it has. Earlier releases refuse the upgraded file; to go back to one, restore the backup.

See the [command reference](../command-reference.md#accounts-and-the-current-repository) for details. The [changelog](../../CHANGELOG.md) lists every release.
